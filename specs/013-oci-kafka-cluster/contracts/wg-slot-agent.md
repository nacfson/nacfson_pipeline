# Contract: WireGuard Slot Agent (GKE side of the tunnel)

**Implements**: FR-008, FR-009, FR-022, FR-030, SC-009 | **Namespace**: `oci-link` (GKE only, removable after a move)

## Kubernetes objects

| Object | Owner | Contents |
|---|---|---|
| `Namespace/oci-link` | Flux | platform namespace, Restricted pod security not enforced (host network), admitted by preflight for this DaemonSet only |
| `ConfigMap/wg-slot-pool` | Flux (Git) | `slots`: the slot numbers in the pool, `0,1,2,3` at start, each within 0–13. Generated by kustomize `configMapGenerator`, so its name changes with its content |
| `Job/wg-slot-keygen` | Flux | mounts `wg-slot-pool` and carries `kustomize.toolkit.fluxcd.io/force: enabled`, so Flux re-runs it on every pool change. Creates a key for each listed slot that has none, never overwrites an existing key, and removes the key and public entries of a slot no longer listed once its Lease has no live holder (otherwise it exits non-zero and the Job retries) |
| `Secret/wg-slot-keys` | keygen Job | `slot-<n>.key` per listed slot (WireGuard private keys) |
| `ConfigMap/wg-slot-public` | keygen Job | `slot-<n>.pub`, `slot-<n>.address` per listed slot |
| `ConfigMap/wg-peers` | Flux (Git) | `peers.json`: a JSON list with one entry per broker (`name`, `publicKey`, `endpoint` = reserved public IP and port 51820, `address` = VCN `/32`). Generated by kustomize `configMapGenerator`, so a change rolls the DaemonSet |
| `Lease/wg-slot-<n>` | slot agent | one per listed slot, created by the first agent that claims it; holder = node name; annotations per [ops-events-and-metrics.md](ops-events-and-metrics.md) |
| `DaemonSet/wg-slot-agent` | Flux | `hostNetwork: true`, `NET_ADMIN` only, read-only `hostPath /var/lib/fluent-bit-state`, requests = limits 10m / 32Mi |
| `Event` (`NoFreeSlot`, `TunnelStale`, `TunnelRecovered`) | slot agent | `involvedObject` is the agent's own Pod in `oci-link` (an Event in a namespace must name an object there); `source.host` is the GKE node name, which the relay reads |
| `ServiceAccount`, `Role`, `RoleBinding` | Flux | leases get/list/watch/create/update, events create, both in `oci-link`; nodes get (ClusterRole) |

## Behaviour on each node

1. **Claim**: read `wg-slot-pool` and list the Leases. Only slots in the pool that have a key in `wg-slot-keys` can be claimed. Take the lowest such slot whose Lease is missing, has expired, or whose holder is not a current Node: a missing Lease is created, an existing one is taken by an `update` with the observed `resourceVersion`. If the create or update conflicts, re-list and try the next slot. If no slot is free, emit Event `NoFreeSlot` (type Warning, reason `NoFreeSlot`) and retry every 30 s. Do not start a tunnel.
2. **Bring up** (idempotent):
   - interface `wg0` with private key `slot-<n>.key` and address `10.201.0.<n+1>/32`
   - one peer per entry in `wg-peers`, with `AllowedIPs` = that broker's `/32` and `PersistentKeepalive 25`
   - routes `10.200.0.11/32`, `.12/32`, `.13/32` dev `wg0`
   - nftables table `oci_link` with one rule: `oifname "wg0" snat to 10.201.0.<n+1>`
3. **Renew** every 30 s, writing the two metric annotations. Read the buffer size by summing `/var/lib/fluent-bit-state/chunks`. Read the handshake age with `wg show wg0 latest-handshakes`.
4. **Stale tunnel**: if every peer's handshake is older than 180 s, emit Event `TunnelStale` once. When it recovers, emit `TunnelRecovered`.
5. **Release** on SIGTERM: delete `wg0` and table `oci_link`, then clear the Lease holder. Also release when the held slot is removed from `wg-slot-pool`, then claim another listed slot. Fluent Bit buffers during that short reconnect.
6. **Never** touch any interface, route, or nftables table it did not create.

## OCI side (Ansible, per broker VM)

- `wg0` with the broker's own key (generated on the VM; the public key is copied into `wg-peers` through a pull request), `ListenPort 51820`
- one `[Peer]` per slot: public key from `wg-slot-public`, `AllowedIPs = 10.201.0.<n+1>/32`

## Changing the pool (resize or key rotation)

The pool works like a connection pool: nodes borrow slots, and Git sets the pool's size.
- **Grow**: add slot numbers to `wg-slot-pool`, copy the new public keys into `wireguard_slots.yml`, and merge. The automated run (FR-031) registers them on the brokers.
- **Rotate a key**: add a replacement slot as above, then remove the old slot from `wg-slot-pool` and `wireguard_slots.yml` in a second merge. The node holding it moves to a free slot.
- The pool always keeps at least the GKE maximum node count plus one (FR-022).
- nftables on `wg0`: accept TCP 9092 to the VCN address, drop everything else

## Spike S1 and fallback

The SNAT rule must work for pod traffic under GKE Dataplane V2 (research R6). If quickstart Scenario 0 fails, the fallback switches `fluent-bit` and `ops-relay` to `hostNetwork: true` and replaces the SNAT rule with `ip route replace 10.200.0.0/24 dev wg0 src 10.201.0.<n+1>`. Everything else in this contract is unchanged.
