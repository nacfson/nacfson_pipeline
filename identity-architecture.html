Identity architecture, at a glance.

A recoverable single-node identity platform: Google verifies people, Keycloak establishes platform identity, and ProcessManager remains a GitOps control plane—not an authentication server.

Accepted foundation

One explicit authority per concern. No application receives identity database access or platform-wide administrative credentials.

Primary identity
Google

Only initial upstream for personal accounts and normal administrators.

Platform issuer
Keycloak

One realm, one platform issuer, separate client per protected project.

Desired state
Git + Flux

ProcessManager commits configuration; Flux owns Kubernetes mutation.

Availability
Recoverable

One node, one Keycloak pod, one CNPG instance; no HA claim.

Trust boundary

Identity data and administrative APIs are intentionally outside ProcessManager and project responsibilities.

Identity system owns
  • Google identity brokering
  • Platform accounts and sessions
  • Tokens, groups, and roles
  • TOTP and recovery administration
  • Dedicated PostgreSQL credentials
No database or admin API access
ProcessManager owns
  • Access-policy validation
  • Deterministic Helm values
  • Signed Git desired-state commits
  • Read-only deployment observation
  • Audit actor issuer and subject
Breaking cutover: the custom Go password/session service, routes, templates, secrets, bootstrap tooling, and production fallback are removed.
