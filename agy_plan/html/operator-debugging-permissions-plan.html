Operator Debugging Permissions & GitOps Plan

Declarative RBAC extension for cluster-level diagnostics, host VM bootstrap path stabilization, and comprehensive specification synchronization.

Target Architecture K3s Single-Node + FluxCD GitOps
Target Environment vps-k3s / local-k3s (Oracle Linux 9 / Ubuntu 24.04 ARM64)
Governance Layer deploy/platform/governance/
Constitution Alignment Principle I (Continuous GitOps) & Principle V (Vault Isolation)

1. Requirement Verification & Scope Analysis

The operator requires frictionless, secure kubectl debugging capabilities while maintaining full adherence to GitOps and the Ratified Constitution:

Requirement Current Limitation Proposed Resolution Delivery Method
Cluster Node Visibility kubectl get nodes returns Forbidden under operator-readonly because standard view ClusterRole is strictly namespace-scoped. Grant get, list, watch on nodes and nodes/status in a dedicated ClusterRole. GitOps Manifest (Flux)
Workload Metrics Inspection kubectl top node and kubectl top pod fail due to missing metrics aggregation rules. Grant get, list on metrics.k8s.io for nodes and pods. GitOps Manifest (Flux)
Pod Port-Forwarding kubectl port-forward rejected for non-admin accounts. Operators cannot inspect private services (OpenBao, Keycloak). Grant create on pods/portforward. (Subresource allowed by manual-change-policy). GitOps Manifest (Flux)
Host VM Diagnostics Stale KUBECONFIG file and missing /usr/bin/kubectl symlink cause certificate errors and missing commands on Oracle Linux. Ansible bootstrap installs /usr/bin/kubectl and writes a fresh mode-0600 kubeconfig for the SSH user. Ansible Playbook (Spec 003)
Security & Principle Invariant Preserved
Workstation operators will never have read access to Secrets (Principle V) and will never have write access to cluster objects (Principle I). All mutations remain strictly blocked by ValidatingAdmissionPolicy.

2. GitOps Delivery & Architecture Flow

All changes to Kubernetes RBAC will be declared in Git under deploy/platform/governance/. The in-cluster Flux GitOps controller continuously reconciles this layer.

3. Detailed Code Modifications

A. Platform Governance: deploy/platform/governance/operator-access.yaml

Appends the new ClusterRole and binding while maintaining the original operator-readonly-view binding to satisfy CI Invariant 8:

apiVersion: v1
kind: ServiceAccount
metadata:
  name: operator-readonly
  namespace: governance
  labels:
    platform.nacfson.io/managed-by: platform
automountServiceAccountToken: false
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: operator-readonly-view
  labels:
    platform.nacfson.io/managed-by: platform
subjects:
  - kind: ServiceAccount
    name: operator-readonly
    namespace: governance
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: view
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: operator-diagnostics
  labels:
    platform.nacfson.io/managed-by: platform
rules:
  - apiGroups: [""]
    resources: ["nodes", "nodes/status"]
    verbs: ["get", "list", "watch"]
  - apiGroups: [""]
    resources: ["namespaces"]
    verbs: ["get", "list", "watch"]
  - apiGroups: [""]
    resources: ["events"]
    verbs: ["get", "list", "watch"]
  - apiGroups: [""]
    resources: ["pods/portforward"]
    verbs: ["create"]
  - apiGroups: ["metrics.k8s.io"]
    resources: ["nodes", "pods"]
    verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: operator-readonly-diagnostics
  labels:
    platform.nacfson.io/managed-by: platform
subjects:
  - kind: ServiceAccount
    name: operator-readonly
    namespace: governance
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: operator-diagnostics

B. Host Bootstrap Automation: bootstrap/tasks/install.yml

Symlinks standard binaries to prevent path errors on RHEL/Oracle Linux, and provisions clean user-level kubeconfig:

    - name: Ensure symlinks exist for k3s and kubectl in standard PATH locations
      ansible.builtin.file:
        src: "/usr/local/bin/k3s"
        dest: "{{ item }}"
        state: link
        force: true
      loop:
        - "/usr/bin/k3s"
        - "/usr/bin/kubectl"
        - "/usr/local/bin/kubectl"

    - name: Ensure target user kube directory exists
      ansible.builtin.file:
        path: "~{{ ansible_user }}/.kube"
        state: directory
        owner: "{{ ansible_user }}"
        mode: "0700"

    - name: Provision fresh target user kubeconfig
      ansible.builtin.copy:
        src: "/etc/rancher/k3s/k3s.yaml"
        dest: "~{{ ansible_user }}/.kube/config"
        remote_src: true
        owner: "{{ ansible_user }}"
        mode: "0600"
